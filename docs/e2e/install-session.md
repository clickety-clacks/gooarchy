# Install, update and session

Run independently on a disposable Arch installation or an isolated machine whose current state can be restored. Use the candidate distro tag/commit and its actual published package repository. Save the installer log and package list. Do not run an installer over someone's daily desktop to gather evidence.

1. **Fresh install.** Install from the candidate's documented command and observe the first login. `pacman -Q gooarchy gooarchy-flavorings scottland` must identify the candidate's selected versions. The installer must select the intended signed repository and packages, report any setting it overrides, and stop with a useful error if a required package cannot be obtained. Record the source tags and archive hashes used by the installer. This checks Gooarchy's package selection and failure behavior, not the third-party package build itself.
2. **Session start.** Log out and log in again through the supported entry point. Scottland/Wayfire must start with the installed configuration; a terminal opens with Super+Enter, Chromium with Super+Shift+B, and Strata with Super+Shift+F. Check that the configured keyboard layout is inherited. Record the active session type and the observed windows.
3. **User choices and rerun.** In a disposable test account, choose a nondefault theme and change one user configuration value managed by Gooarchy. Run the installer again at the same candidate. It must leave the existing choice alone or explicitly report a supported override; it must not replace a symlinked user configuration file. Inspect the affected value, not just installer exit status.
4. **Update.** Starting from the preceding released version, use the documented update path to install the candidate packages. Log out and start a fresh Scottland login. Verify the new package identities and one changed user-visible behavior named in the release notes; a process still running old executable bytes is not update acceptance. Confirm the prior user choice remains as the product contract requires.
5. **Exit and recovery.** Log out normally, then start another session. There must be no leftover task-owned compositor or Gooarchy session process preventing login. In a separate disposable session, exercise the supported failed-start/recovery path and verify that it returns to a usable login instead of leaving an authenticated shell or replacing an unrelated session.

Record each step's result and the relevant install log under the run's evidence directory. Restore the disposable snapshot or remove only files this run created. If a package/repository is not yet published, mark the install and update steps `BLOCKED` with that exact missing artifact; do not substitute a source checkout and call it a release install.
