# Final distro end-to-end pass

Run this only for a proposed Gooarchy distro release, after its package/tag identities and installation route are fixed. The four [independent runbooks](README.md) may be run in any order, on any capable isolated machines; each must name its own candidate and evidence. A result from a different revision does not transfer. The final pass collects them and checks that the installed release contents match the candidate manifest.

1. Run [install and session](install-session.md), [windows and input](windows-input.md), [appearance and defaults](appearance.md), and [desktop integrations](integrations.md) fully. For each, record the candidate commit/tag, package identities, `PASS`/`FAIL`/`BLOCKED`/`NOT SHIPPED` steps and evidence location. Re-run only affected steps when a candidate changes, then reconcile the whole result against the new installed identities.
2. Compare the result with the release's declared custom features and [DEFICIT.md](../../DEFICIT.md). Every shipped Gooarchy, Flavorings and Scottland behavior should have an observed assertion in one runbook; add a focused step for a newly shipped behavior before claiming full coverage. Do not turn a tool, hostname, machine ID or incidental setup check into product acceptance. Keep actual isolation, review, access and one-use controls for safe execution.
3. **Run the attended per-screen zones check on the target display:** record the current zones, disconnect and reconnect the display, and verify the zones and window placement return as intended. Record the operator's observation and the installed Scottland version. This is a final-release human check, not a prerequisite for unrelated coding, review or earlier runbooks. Do not remotely alter the target desktop to perform it.
4. **Run the Adapter B real-seat keep-mode check** if the release includes that adapter behavior. Ask an operator to exercise keep-mode in the target desktop session and report whether its visible mode and user state persist as specified. Record the exact installed adapter version and the operator's observation. Do not infer this result from a headless or simulated check, and do not hold unrelated source work for this final prompt.
5. State the release decision with each failed or blocked behavior, its owner and remedy. A published source tag, passing CI, package installation or a completed subset of these runbooks is not a full end-to-end pass.

Suggested result heading: `Candidate <tag/commit>; package manifest <path/hash>; runbook results <paths>; attended operator checks <result/date or pending>; remaining failures and owners <list>; release decision <accepted/held>`. Keep evidence with the release record; do not write private machine identifiers into this public repository.
