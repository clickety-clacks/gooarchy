# Desktop integrations

Run independently in a fresh isolated Scottland session with the candidate packages installed. Use test files and accounts only. Confirm the visible action at each boundary rather than testing a third-party application's internal features.

1. **Files and defaults.** Open a test directory through Gooarchy's folder action and verify Strata receives that directory. Use a supported “show in folder” action from an application and verify the expected directory opens. Open a web link and verify the configured browser receives it. Record the selected default-handler identities.
2. **Portals.** From a test application, open a file chooser, request one screenshot and one screencast. The user must see the intended chooser/selection flow, and the application must receive the selected file or image/stream. Record which installed portal backend handled each request. A portal configuration file or package listing alone does not pass the request.
3. **Capture and clipboard.** Use Gooarchy's screenshot shortcut and verify that the output appears in the user's configured Pictures location. Copy and paste text between two ordinary windows, including the candidate's clipboard-history action if shipped; confirm the selected content reaches the focused target and unrelated clipboard contents are not silently overwritten.
4. **Notifications and attention.** Send a test notification from an application and verify it appears in Scottland with the intended action/expiry behavior. Ring a test terminal bell and verify Scottland attention identifies the correct window. If the candidate ships a do-not-disturb or reminder command, verify its user-visible effect and recovery separately. Do not treat a daemon package or D-Bus name as the outcome.
5. **Audio and tools.** Play a short test sound, use the Gooarchy/Scottland volume and mute actions, and verify audible or measured output changes and restores; no physical speaker is required if a controlled audio sink shows the behavior. Invoke each Gooarchy-owned installed tool promised by the candidate once through its public command or UI and check its specific visible effect and failure message. Record the installed binary/package identity and behavior; do not count a source-only or off-host unit test as an installed result.

Mark an optional integration `NOT SHIPPED` only after checking the candidate manifest. Save the portal, clipboard and attention observations, then remove test files and restore the test account's defaults. Do not exercise unrelated third-party application functionality.
