# WI854 Card90 guest scenarios

Prepared for Gooarchy source `2eaf752afd82384b1a4a947373c2cdfa0980d59c`, tree `7d5d0c244d54c4b61f79d393e0add98781c589aa`, public release `440822085`. Expected shipped package identities from the approved release notes are Gooarchy `0.0.1.r329.g2eaf752-1`, Scottland core, Omarchy adapter, and Sunlight `0.4.1-1`, and Flavorings `0.2.2-1`. At action time, independently rebind the public release manifest and exact archive hashes before installing the candidate in fresh disposable guests.

The guest-side driver is `card90-scenarios.sh`. It adds no product hook or test mode. The canonical `tests/vm/run.sh` remains unchanged (SHA-256 `ba5c186d769e68b95b67427a7a0d43f3eb78f041d9751ee4e92a914f83e877ac`). The wrapper copies tracked and untracked checkout files into `~/gooarchy`; invoke that copy by a remote command, never by redirecting the driver to `bash -s`. A remote command avoids the wrapper's stdin-free RPC fallback and its zero exit for an empty `bash -s`. The remote command requires a run-specific `RESULT` line, so absent guest evidence cannot count as success:

```bash
card90_case() {
  local case_name=$1 run_id=$2 arg qargs remote evidence marker
  shift 2
  printf -v qargs '%q %q' "$case_name" "$run_id"
  for arg in "$@"; do printf -v q '%q' "$arg"; qargs+=" $q"; done
  evidence="/var/cache/pacman/vm-test/card90-evidence/$run_id/observations.txt"
  printf -v marker 'RESULT case=%s run_id=%s outcome=' "$case_name" "$run_id"
  printf -v remote 'cd "$HOME/gooarchy" && CARD90_DISPOSABLE_GUEST=yes bash tests/vm/card90-scenarios.sh %s; rc=$?; grep -F %q %q >/dev/null || exit 90; exit "$rc"' "$qargs" "$marker" "$evidence"
  GOOARCHY_VM_DIR="$vm_dir" tests/vm/run.sh ssh "bash -lc $(printf '%q' "$remote")"
}
```

Use a distinct fresh `GOOARCHY_VM_DIR`/guest per scenario, bound to the wrapper's task-owned package-cache mount. The first scenario invocation uses a new run ID whose evidence directory does not exist. The driver records output, exit codes, fixture identities, and `RESULT` lines under `/var/cache/pacman/vm-test/card90-evidence/<run-id>/`, the wrapper's per-VM host-backed cache mount. Only `verify-update-login` and `verify-snapshot-boot` may reuse the same run ID, and only with the existing run-owner marker and observations file present. Use the same VM directory for the related reboot and verification phase. After checks, capture and hash evidence outside the disposable VM directory; stop the VM through the wrapper, then discard only that run's VM directory. Do not delete or modify other run data. The driver does not try to restore package/cache fixture changes in place.

| Case | Fixture and preconditions | Expected observation |
| --- | --- | --- |
| `wayfire-rollback-update` | Installed release candidate; saved Gooarchy plan says `GOOARCHY_BUILD_LOCAL_SCOTTLAND=1`; supported root filesystem/snapshot layout; exact Wayfire and matching Scottland package archives plus a source manifest in this VM's package-cache mount. Arguments bind both archive paths, SHA-256 values, package versions, manifest path, and manifest SHA-256. The driver verifies those values, package metadata, and the Scottland archive's exact Wayfire dependency before installation. | The package transaction advances Wayfire to the current repository version; local Scottland rebuild completes from its configured pin; update reports completion. On Btrfs, capture the update snapshot; on another filesystem, capture the documented no-snapshot notice. The initial result explicitly leaves the post-login working session unproved. In the same VM, run the unchanged wrapper's `reboot`, `check`, and `login-check`, preserve their actual results, then call `verify-update-login` with the same run ID. That phase verifies the saved package pair and Wayfire process; wrapper check/login-check evidence supports the working-session conclusion. |
| `rebuild-failure` | Same exact matched archive pair and local-Scottland/layout preconditions as above. The driver records guest-local `/etc/makepkg.conf.d/rust.conf`, appends a unique invalid Rust compiler flag there (not to the overridden environment), then sources `/etc/makepkg.conf` followed by each `/etc/makepkg.conf.d/*.conf` in makepkg load order and confirms the effective setting. This deliberate config change is only inside the disposable guest, which is discarded afterward. | The update log must contain the unique flag in the Rust compiler error diagnostic itself, and the pacman log must prove Wayfire changed first. A generic update/pacman/network error is not a pass. Update exits unsuccessfully, reports pair restoration, and installed versions match the pre-update pair. The driver leaves bootability and a working session after restart unproved. In the same VM, run the wrapper's `reboot`, `check`, and `login-check`; preserve their actual results, then call `verify-update-login` with the same run ID. |
| `missing-cache` | Fresh candidate guest; local Scottland plan and supported root/snapshot layout are recorded. The driver checks package-cache/recovery paths remain within this guest or its unique run mount, removes only copies of the exact installed Wayfire or Scottland archive, records their hashes, and verifies none remain. | Update refuses before package changes, names the missing package and version, and leaves the installed pair and pacman log unchanged. |
| `boot-snapshot` | Btrfs root and existing same-filesystem `/.snapshots` subvolume; booted root uses Btrfs's default subvolume and boot config does not explicitly select a root subvolume. | Driver takes and lists a uniquely labelled snapshot, requests restore, verifies the safety snapshot and unchanged boot-file digest, and reports next-boot selection. This is not reported as completed restore. In the same VM, run the unchanged wrapper's `reboot`, `check`, and `login-check`, then call `verify-snapshot-boot` with the same run ID. | `source-edit-rollback` | Clean guest-local Scottland source working clone and installed source-build mechanism. No PTY or stdin script is used: a remote command invokes the copied driver through `run.sh ssh`. `scottland-source edit scottland --path` returns the tool member directory inside the clone; the driver locates the Git root from there and checks the root worktree is clean. It edits that member's `main.rs`, then uses `scottland-source edit ... --no-editor --message` and rollback commands. | Installed source identity changes on rebuild, then returns to the exact original commit on rollback. This proves the source-management/build identity path only, not unrelated feature behavior. |

The first three cases record local-Scottland selection and root filesystem on each run. If Btrfs lacks the supported snapshot layout, the case is `NOT_REACHED`, not a Gooarchy failure; non-Btrfs update cases retain the release-notes no-snapshot result. A mismatched installed package set, absent/mismatched fixture or manifest, unsupported cache path, or missing source precondition is also `NOT_REACHED`. Fixture installation failure before assertions is `NOT_REACHED` and its output is retained. Each scenario and verification phase needs its own explicit `RESULT` line; absent evidence is never success. Verification phases use the original run ID and VM directory and are the only invocations permitted to reuse existing evidence. For the working-session claim, preserve the wrapper's actual `check` and `login-check` outputs as well; the driver package/process readback alone is not a visual or interactive desktop check.
